# LAN Audio

局域网内的双向声音传输：

- **手机内部 App 声音 → 电脑**（Android 10+，静音、音量 0、锁屏都能继续）；没有声音时自动停止上传，空闲不再占用约 1.5 Mbps
- **手机麦克风 → 电脑**
- **电脑系统声音 / 标签页声音 → 手机**（Windows，需要 Edge 或 Chrome）
- **电脑麦克风 → 手机**（Firefox / Edge 都可以）
- **手机 ↔ 手机互传**：发送给手机、接收到手机各自独立，与电脑方向互不影响
- **一托多**：一个房间可同时连 **2–4 台手机**，所有手机的声音自动混音到电脑；每台可单独静音、调音量、断开
- **麦克风独立处理**：麦克风增益（发送端 / 电脑每设备接收端）、电脑端降噪、左/中/右声道，都只作用于麦克风，不影响手机内部声音
- **电脑控制手机**：网页可远程切换手机音源、发电脑、收电脑，切换后正在发送的声音会自动恢复，不用再按“开始发送”
- **电脑麦克风本地监听**：只在本机播放，绝不会发送给手机；可与“麦克风发送给手机”同时开启；最高 300% 音量并带独立降噪
- **独立麦克风采样率**：手机麦克风默认 24 kHz，可单独选 16 / 24 / 48 kHz，与内部声音采样率互不影响
- **全局快捷键**：目标选择、发/收开关、音源切换、电脑静音、本地监听等全部可自定义；留空即禁用，保存在 `%APPDATA%\LAN Audio\hotkeys.json`
- **每设备接收缓冲**：每台手机可单独设 20–400 ms 接收缓冲；全局滑块可一键改所有设备，之后仍可逐台微调
- **平衡缓冲**：开关打开时所有设备统一取最大目标缓冲，便于多设备对齐；关闭时各用各的。目标缓冲最高 550 ms，实际数据硬裁剪 750 ms，不会再出现 900 ms
- **限幅与防爆音**：手机麦克风 500% 增益、电脑每手机 300% 音量均带软限幅；接收端起播做 20 ms 余弦淡入，短欠载保持输出并平滑衰减，不会跳变爆音
- **单前端控制**：同一时间只允许一个电脑页面控制声音。每台电脑声音只播一路，避免多页面叠加导致音量调节失效；再开新页面会显示"此页面只读"横幅
- 电脑声音会广播给房间内所有手机

电脑端是网页（磨砂玻璃 UI），手机端是原生 Android App。全部走局域网，不经过任何云端，不落盘。

当前手机 App 版本：**1.5**（versionCode 6）。

## 1. 快速开始（电脑）

### 推荐：`release\exe\LAN Audio.exe`

`release\exe` 是解压即用的完整包，**不需要安装 Node.js**：

1. 解压整个 `release` 文件夹（不要只复制单个 exe）。
2. 双击 **`LAN Audio.exe`**。
   - 它会在后台启动 `lan-audio-backend-2026.exe`，**不弹黑色命令行窗口**。
   - 通知区域（托盘）会出现 LAN Audio 图标；双击图标打开电脑页面，右键可退出。
   - 浏览器会自动打开电脑页面（默认 `http://localhost:8080/`）。
3. 首次运行如弹出 Windows 防火墙提示，请勾选 **专用网络** 并允许。
4. 页面会显示 4 位房间码（默认 `8888`）。

**单实例防多开**：再次双击 `LAN Audio.exe` 不会启动第二个服务，只会打开已有页面。
即使直接双击后端 exe，第二个实例也会检测到“已经在运行”并立即退出。这样可以避免两个服务抢端口、手机和电脑页面连到不同服务端而导致收不到声音。

**端口自动顺延**：如果 8080 被其他程序占用，服务会自动改用 8081、8082……，并通过 UDP 自动发现把新端口告诉手机。电脑页面始终以托盘/日志里显示的端口为准。

> `LAN Audio.exe` 是启动器（无窗口 + 托盘）；`lan-audio-backend-2026.exe` 才是真正的服务进程。
> 不建议直接双击后者（名字不显眼，也不会显示托盘图标）。

### 从源码运行

1. 安装 [Node.js](https://nodejs.org/) 18+。
2. 在项目根目录双击 `start.cmd`，或执行：

```bat
npm install
npm start
```

> 电脑页面必须用 `localhost` 打开，不要用 `192.168.x.x`，否则 Edge 不允许捕获系统声音。

## 3. 使用步骤

### 手机 → 电脑

1. 手机与电脑连接同一个 Wi-Fi。
2. 打开 App，点 **发现**（或手动填电脑 IP，端口默认 8080）。
3. 选择音源：
   - **手机内部声音**：音乐、视频、游戏等（最常用）。
   - **麦克风**：说话声。选择这一项时**不会再弹屏幕录制授权**。
   - **内部声音 + 麦克风**：混音（这一项仍需要屏幕/音频授权）。
4. 点 **开始发送**。选择“手机内部声音”或“内部声音 + 麦克风”时，系统会弹出“录制或投屏”授权 —— 这是 Android 抓内部声音的强制步骤，**只抓音频，不录画面**，点“立即开始”。
5. 电脑网页点 **启用音频输出**，即可听到手机声音。

> **发送和接收是独立的**：只点“开始接收”不会采集手机声音，也不需要录音/投屏授权；只点“开始发送”不会播放电脑声音。运行中切换音源会自动用新音源恢复发送，接收不受影响。

### 电脑 → 手机

1. 在电脑网页点 **共享系统 / 标签页声音**。
2. 在 Edge 的弹窗里选择：
   - **整个屏幕** + 勾选 **共享系统音频**（推荐，能抓到所有应用声音）
   - 或 **标签页** + 勾选音频（只抓该标签页）
3. 手机 App 点 **开始接收**（“播放电脑声音”保持开启），即可听到电脑声音。

> 手机端播放走的是**媒体音量**通道，请用手机侧边音量键把“媒体音量”调大；App 里的“播放音量”默认 100%。
> 需要更响可打开 **2× 音量增强**（可能失真）。

### 手机 ↔ 手机互传

“手机互传”卡片里有两组完全独立的按钮：

- **发送给手机 / 停止**：把本机采集到的声音发给另一台手机。
- **接收到手机 / 停止**：接收另一台手机发来的声音。

先在“目标手机”下拉框里选择同一房间内的另一台手机。这两组按钮与“发送到电脑 / 接收电脑声音”互不影响，可以只开其中一个。

### 电脑控制手机 / 本地监听

“已连接手机”卡片里每台手机都有：

- **音源**：内部声音 / 麦克风 / 内部 + 麦克风，电脑可直接切换手机采集源。
- **发电脑 / 收电脑**：远程开关手机的上传和接收。即使关掉最后一路，手机仍会保持连接 5 分钟，方便再从电脑打开；5 分钟内无操作则自动断开。电脑远程停止发送时会保留本次已授权的内部声音权限，因此再次远程开始发送不需要重新在手机上点授权；手机本地停止或 5 分钟超时后才释放。
- 正在发送时切换音源会自动恢复发送；如果从“麦克风”切到“内部声音”而手机还没授权过投屏/音频，手机会提示需要先授权一次。首次授权后，本次服务存活期间电脑可反复远程开关。
- **电脑降噪**只处理这台手机的麦克风帧，0–100，默认 0；不影响手机内部声音。

“电脑麦克风本地监听”卡片用于在电脑上听自己的麦克风。它走独立本地输出，不会发送给任何手机；用扬声器时可能啸叫，建议戴耳机。

### 全局快捷键

页面“全局快捷键”卡片中点击输入框后直接按组合键，留空表示禁用。默认只预填：

- `Alt+P`：控制目标 = 全局
- `Alt+0`：控制目标 = 设备 1
- `Alt+9`：控制目标 = 设备 2

设备槽按 Android 设备 ID 自动绑定，重连后不会因连接顺序变化而换机；也可在快捷键卡片里手动改绑。其他动作键默认全部留空，按需自定义。快捷键由托盘启动器通过 Windows `RegisterHotKey` 注册，所以在任何窗口都生效；冲突项会在页面显示注册失败原因。未启动 `LAN Audio.exe` 时，页面聚焦状态下仍可使用这些快捷键。

控制多台手机时，手机命令按**绝对状态**下发：`发电脑 全部开/关`、`收电脑 全部开/关`、`麦克风传输 全部开/关` 会先判断整组状态，再让每台手机收到同一个目标值，不会出现一台开、一台关时各自反转。需要明确开关时可直接绑定 `发电脑：开（绝对）`、`发电脑：关（绝对）`、`收电脑：开（绝对）`、`收电脑：关（绝对）`。单台设备槽同样适用这些命令。

### 同时双向

- 默认是 **自动半双工**：共享“整个屏幕/窗口”时，网页会自动静音手机声音的本地播放，防止声音绕回手机。
- 想要真正同时双向：
  - 戴耳机，且电脑端改为 **共享单个标签页**（不要共享整个屏幕），或
  - 在网页“双向模式”里选择 **全双工**，并自行注意回声。
- 手机端回放使用独立音频通道，不会被自己的内部声音采集再次抓走。

### 一托多（多台手机同时连电脑）

1. 电脑网页保持打开，房间码不变（默认 `8888`）。
2. 其余手机安装 APK，填写**同一个电脑 IP** 和**同一个房间码**。
3. 电脑网页的“已连接手机”卡片会列出每台手机：名称、采样率、实时码率、收发状态。
4. 所有手机的声音会**自动混音**到电脑；每台可单独静音、调音量、断开。
5. 电脑端“发送到手机”会**同时广播**给房间内所有手机。

> 建议 2–4 台手机。每台约占 1.5 Mbps 上行，手机更多时建议把采样率降到 24 kHz 或 16 kHz。

## 4. 可调项

电脑网页：

| 项目 | 说明 |
|---|---|
| 采样率 | 48 kHz（音乐）/ 24 kHz（标准）/ 16 kHz（语音） |
| 声道 | 立体声 / 单声道 |
| 发送增益 | 0–200% |
| 全局接收缓冲 | 20–400 ms，改一次应用到所有已连接设备（网络差时调大） |
| 双向模式 | 自动半双工 / 全双工 |
| 回声消除、降噪 | 仅作用于麦克风 |
| 播放音量 / 静音 | 接收手机声音 |
| 平衡缓冲 | 开 = 所有设备取最大目标缓冲，多设备更齐；关 = 每台用自己的值 |
| 电脑麦克风本地监听 | 独立音量 0–300% + 降噪 0–100，只在本机播放，不发送给手机；高音量经软限幅 |

每台手机的卡片里还有（按设备独立）：

| 项目 | 说明 |
|---|---|
| 音量 | 0–300%，接收该手机的声音，带软限幅 |
| 麦克风增益 | 0–500%，只放大麦克风帧，内部 App 声音不变，带软限幅 |
| 电脑降噪 | 0–100，只处理该手机的麦克风帧；0=关闭，建议 30–70 |
| 麦克风声道 | 左 / 中 / 右，把该设备的麦克风定位到一侧 |
| 接收缓冲 | 20–400 ms，本机目标缓冲；拖动后约 0.2 s 自动生效，松手立即生效 |
| 追赶速度 | 0–100 连续可调：0≈1.005x，100=1.15x；缓冲过多时平滑追上，剩余少于 60 ms 时提前减速，不会倍速跳变 |
| 缓冲显示 | 实际 / 目标缓冲（ms），目标含少量自动补偿 |

以上设置按 Android 设备 ID 保存在浏览器本地，重连后自动恢复；旧版 App（1.1 及以前）没有独立麦克风帧，这些控件会自动置灰。

手机 App：

| 项目 | 说明 |
|---|---|
| 音源 | 内部声音 / 麦克风 / 混合 |
| 采样率、声道 | 内部声音/电脑方向的格式 |
| 麦克风采样率（独立） | 16 / 24 / 48 kHz，默认 24 kHz；只影响麦克风上传，修改后重新开始发送生效 |
| 回声消除、降噪 | 麦克风 |
| 播放开关、音量 | 接收电脑声音，运行中可实时调整 |
| 2× 音量增强 | 软件放大 2 倍，声音更响，但可能失真 |
| 系统降噪 | Android 自带的 `NoiseSuppressor`，只能开/关 |
| 麦克风增益 | 0–500%，只作用于麦克风，在降噪之后放大，带软限幅 |
| 降噪强度 | 0–100 连续滑块：0=关闭，25=普通，60=强，100=超强；只作用于麦克风 |
| 手机互传 | 选择目标手机，发送/接收各自独立开关 |

降噪处理链：90 Hz 高通 → 噪声门/向下扩展器 → 可选谱减（强度 >25 时）→ 增益。强度越高底噪越干净，但过高可能出现轻微“水声/发闷”，建议先用 60 左右。

设置会自动保存。

## 5. 已知限制

1. **Firefox 无法捕获电脑系统声音**（`getDisplayMedia` 会丢掉音轨）。Firefox 仍可接收手机声音、使用麦克风。抓电脑声音请用 Edge/Chrome。
2. **手机网页无法抓内部声音**，所以手机端必须是 App。
3. **部分 App 禁止被录制**（Netflix、部分 DRM 内容）会得到静音，无法绕过。
4. **Android 10+**（API 29+）；更老的系统不支持内部声音采集。
5. 手机锁屏后由前台服务继续采集；部分厂商的省电策略可能杀后台，需要在系统设置里允许自启动 / 关闭电池优化。
6. 音质/延迟：PCM 未压缩，48 kHz 立体声约 **1.5 Mbps/方向**，局域网无压力；延迟约 **80–150 ms**。手机内部声音连续静音 300 ms 后停止上传（空闲约 0 Mbps），麦克风开启时麦克风流仍持续上传。
7. 手机与电脑必须在同一网段；访客 Wi-Fi / AP 隔离会导致连不上。
8. 浏览器麦克风权限按“源”记忆：同一 `http://localhost:端口` 通常只问一次；端口变化、换浏览器、无痕窗口、清除站点数据后会重新询问。用局域网 IP 打开页面时 Chromium 可能禁止麦克风/屏幕捕获，电脑端请用 `localhost`。
9. 未签名的 exe 首次运行可能触发 SmartScreen，点“更多信息 → 仍要运行”。

## 6. 端口与防火墙

| 用途 | 端口 |
|---|---|
| 网页 + WebSocket | TCP 8080（被占用时自动顺延 8081、8082……） |
| 手机自动发现（UDP 广播） | UDP 8082 |

如果自动发现失败，直接在 App 里填电脑 IP（`ipconfig` 查看），端口填电脑页面显示的端口，并确认防火墙允许程序访问专用网络。

## 7. 重新构建

### 电脑端单文件 exe（Node SEA）

```bat
node tools\sea\build.js
```

产物：

- `release\exe\lan-audio-backend-2026.exe`：服务端单文件 exe（内嵌网页 + `ws`）
- 启动器 `release\exe\LAN Audio.exe` 由 `tools\sea\launcher\Launcher.cs` 编译：

```bat
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /target:winexe /optimize+ ^
  /win32icon:tools\sea\appicon.ico /out:"release\exe\LAN Audio.exe" ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll /r:System.Web.Extensions.dll ^
  tools\sea\launcher\Launcher.cs
```

### Android APK

需要：

- Android SDK（platform 35 / build-tools 35.0.0）
- Gradle 8.11.1（或直接用 Android Studio 打开 `android/`）
- JDK 17

把 `ANDROID_HOME` 指向你的 SDK 目录，然后：

```bat
cd android
gradle assembleRelease
```

在 Android Studio 中也可以直接执行 `assembleRelease` 任务。

Release 产物在 `android\app\build\outputs\apk\release\`。需要使用
`zipalign` 和 `apksigner` 以及你自己的 keystore 签名后才能安装。

签名示例（不要提交 keystore 和密码）：

```bat
zipalign -f 4 app-release-unsigned.apk app-release-aligned.apk
apksigner sign --ks your-release.jks --out lanaudio-release.apk app-release-aligned.apk
```

`apk\`、`release\` 和 `dist\` 是本地构建/发布目录，已加入 `.gitignore`。

## 9. 传输协议（便于二次开发）

- WebSocket：`ws://<电脑IP>:8080/ws?room=8888&role=phone`（`role=pc` 或 `phone`）
- 一个房间支持**多台电脑页面** + 多台手机。
- 帧格式统一：**帧首字节是来源 ID**，`0` = 电脑，`1..255` = 手机 ID。接收方据此区分来源。
- 手机发出的帧首字节是**目标 ID**：`0` = 电脑，`1..255` = 另一台手机。服务端转发时会先剥掉目标字节，再在最前面加上来源字节。
- 手机 App 1.2+ 会把**内部声音和麦克风拆成两帧**分别发送，帧类型分别为 1 和 2，这样电脑端可以只对麦克风做增益/声像/降噪/延迟。
- 手机 App 1.3+ 对内部声音做静音抑制：连续 300 ms 接近数字静音后不再发送该流，有声音时自动恢复；麦克风帧不受影响。

音频帧二进制（20 ms 一帧）：

```
byte 0  : 来源 ID（0=电脑，>0=手机）
byte 1  : 帧类型 1=内部/普通声音，2=麦克风
byte 2  : 采样率  1=16k 2=24k 3=48k
byte 3  : 声道    1 / 2
byte 4  : 保留
byte 5+ : PCM s16le 小端，交错
```

- 文本消息：`{"type":"hello"}`、`{"type":"ping","t":...}`，服务端回 `{"type":"pong","t":...}`。
- 手机状态：`send`（发电脑）、`receive`（收电脑）、`sendPeer`（发手机）、`receivePeer`（收手机）四个独立标志。
- 接收端每台设备默认 90 ms 抖动缓冲（可设 20–400 ms）。开启平衡缓冲时所有活动流取最大目标；自动补偿最多 80 ms，目标缓冲上限 550 ms。
- 缓冲过多时不再直接丢样本：每台设备用 0–100 的追赶滑条控制播放速度（1.005x–1.15x），剩余差值小于 60 ms 时提前平滑减速，速度变化有斜率限制，避免倍速跳变。只有实际缓冲超过 750 ms 才自动截断，截断点带 1.5 ms 淡出/淡入消除爆音。人工调大缓冲仍会短暂停顿等到新目标。
- 单实例锁：Windows 命名管道 `\\.\pipe\lanaudio-singleton`；启动器另用命名互斥体 `Local\LANAudio.Launcher.v1`。
